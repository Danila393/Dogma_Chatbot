# Исследование источника данных dogma.ru

Дата исследования: 24.11.2026. Исследование проводилось в браузере: открывались страницы
`https://dogma.ru/kvartiry` и карточки лотов, анализировались сетевые запросы, которые
выполняет сам сайт при обычной работе с каталогом (смена города, фильтр «Студия»,
кнопка «Показать ещё»). Отдельных «зондирующих» запросов к API с произвольными
параметрами не выполнялось — всё, что описано ниже, получено из запросов самого сайта.

## 1. Как устроен сайт

- `dogma.ru` — приложение на Next.js (App Router, `_rsc`-запросы, чанки `/_next/static`).
- Первая страница каталога рендерится на сервере, дальнейшая подгрузка и фильтрация
  выполняются браузером через **публичный JSON API** на поддомене `service.dogma.ru`.
- Внутренние запросы `dogma.ru/api/fe/*` и `dogma.ru/api/content/v1/filter` относятся к
  формам и баннерам, данных о квартирах в них нет.

## 2. Источник данных о квартирах (выбран: JSON API, приоритет 1)

### 2.1. Список лотов

```
POST https://service.dogma.ru/api/layouts-filter/v4/objects/filter
Content-Type: application/json
```

Минимальное тело запроса, которое отправляет сам сайт при смене города:

```json
{
  "type": 1,
  "statuses": [2],
  "city_ids": [3],
  "order": {"field": "order", "type": "asc"},
  "limit": 12,
  "offset": 0
}
```

| Параметр | Значение |
|---|---|
| `type` | `1` — квартиры (кладовые/паркинги — другие типы, не нужны) |
| `statuses` | `[2]` — лоты «В продаже» (так фильтрует сам сайт) |
| `city_ids` | идентификатор города |
| `rooms` | `[0]` — студия, `[1]`, `[2]`, `[3]` — число комнат |
| `costs`, `areas`, `floors` | диапазоны `[min, max]` (парсеру не нужны) |
| `limit`, `offset` | пагинация |

Ответ:

```json
{
  "status": "200",
  "error": null,
  "data": {
    "count": 12152,
    "objects": [ { "id": 55951, "...": "..." } ]
  }
}
```

### 2.2. Справочник городов и ЖК

```
POST https://service.dogma.ru/api/layouts-filter/v4/config/all
{"type": 1, "statuses": [2], "city_ids": [3]}
```

Возвращает диапазоны фильтров, `count_objects` и справочник
`cities: [{city_id, city_name, projects: [{project_id, project_name}]}]`.
В ответе объектов **нет названия города**, поэтому город берётся из этого справочника.

Наблюдаемые города (из запросов сайта при переключении города):

| city_id | Город | ЖК (project_id: name) | Лотов в продаже |
|---|---|---|---|
| 1 | Новороссийск | 8: Порто-Ново | 548 |
| 2 | Реутов | 2: ЭВО | 271 |
| 3 | Краснодар | 3: МКР Самолёт, 4: DОГМА ПАРК, 5: Рекорд 2, 6: Парк Победы, 11: РИДЗ, 12: САМОЛЁТ 7, 13: ГРЕЙД, 16: Парк Победы 3 | 12 152 |

Итого ≈ 14 900 квартир в продаже. Отдельного эндпоинта «список всех городов» сайт не
вызывает (селектор городов отрисован на сервере), поэтому список `city_id` задаётся в

берутся из `config/all`. Город, для которого API вернул пустой справочник, пропускается
с предупреждением в логе.

## 3. Структура объекта (используемые поля)

Пример (сокращён), лот https://dogma.ru/flat/55951:

```json
{
  "id": 55951, "type": 1, "status": 2, "room": 0,
  "floor": 3, "floor_max": 3,
  "area": 32.3, "cost": 9567260, "cost_sale": 7175445, "square_price": 296200,
  "project_id": 5, "project_name": "Рекорд 2", "letter_name": "3",
  "address": "Краснодар, ул. Новороссийская, 90/2",
  "layout_url": "https://bitrix.1dogma.net/upload/...png",
  "construction_deadline": "...", "flat_number": 16
}
```

| Поле API | Поле модели | Правило |
|---|---|---|
| `id` | `external_id` | строка, уникальна в каталоге (одна последовательность id на все города) |
| `project_name` | `complex_name` | как есть; для поиска — нормализованная форма |
| `project_id` | `complex_id` | идентификатор ЖК на сайте |
| `cost`, `cost_sale` | `price`, `old_price` | см. 3.1 |
| `area` | `area` | `Decimal`, 2 знака |
| `room` | `rooms` | `0` — студия |
| `floor` | `floor` | этаж лота |
| `status` | `source_status` / `status` | `2` → `available` |
| `id` | `url` | `https://dogma.ru/flat/{id}` |
| `address` | `address` | пустая строка → `NULL` |
| `letter_name` | `building` | номер корпуса/литера |
| `layout_url` | `layout_url` | пустая строка → `NULL` |
| `construction_deadline` | `completion_date` | `0000-01-01` или пусто → `NULL` |
| — | `price_per_square_meter` | вычисляется: `round(price / area)` |
| (config/all) | `city`, `city_id` | из справочника городов |

### 3.1. Цена со скидкой

Проверено на карточке лота 55951: сайт показывает `7 175 445 ₽` и зачёркнутую цену
`9 567 260 ₽`. Значит:

- если `0 < cost_sale < cost` — актуальная цена `price = cost_sale`, `old_price = cost`;
- иначе `price = cost`, `old_price = NULL`.

`square_price` в API считается от старой цены (`296 200 × 32,3 ≈ 9 567 260`), поэтому цена
за м² пересчитывается из актуальной цены, чтобы не было расхождений.

### 3.2. Чего в API нет

- **Общей этажности дома.** `floor_max` — это верхний этаж самого лота (для двухуровневых
  квартир), а не этажность дома: у лота 55951 `floor_max = 3`, а на сайте «3 из 24».
  Поле `total_floors` не заполняется, чтобы не придумывать значения.
- **Человекочитаемого статуса.** Сайт запрашивает только `statuses: [2]`, карточка лота
  в JSON-LD пишет «В продаже». Других кодов статусов сайт в каталоге не запрашивает.
- **Названия города** в объекте — берётся из `config/all`.

## 4. Ссылки на лоты

Карточки каталога ведут на `/flat/{id}` (например `/flat/3819`, `/flat/55951`), где `id`
совпадает с `id` объекта в API. Проверено открытием карточки 55951: заголовок страницы
«Студия 32.3 м² №16 по цене 7 175 445 ₽ в Рекорд 2».

## 5. Пагинация

- `limit` / `offset`, в ответе `data.count` — общее количество лотов по фильтру.
- Сайт использует `limit=12`. Парсер использует `PARSER_PAGE_SIZE` (по умолчанию 100) и
  **не полагается** на то, что сервер вернёт ровно столько: если первая страница короче
  запрошенной при большем `count`, фактический размер страницы берётся из ответа.
- Полнота проверяется сравнением числа уникальных `id` с `count`.

## 6. Ограничения сайта и правила использования

- `https://dogma.ru/robots.txt`: разрешены JS/CSS/изображения/JSON, запрещены служебные
  разделы Bitrix, авторизация, URL фильтров и **любые URL с query-string** (`/*?`).
  Парсер не обращается к страницам `dogma.ru` с query-string: данные берутся из API на
  `service.dogma.ru` (POST без query-string), а ссылки `/flat/{id}` robots.txt не запрещает.
- `https://service.dogma.ru/robots.txt` при проверке не был получен (ошибка клиента у
  источника) — правил для поддомена не опубликовано.
- Авторизация, CAPTCHA и токены для API не требуются; запросы идут только с
  `Content-Type: application/json` — так же, как из браузера. Ничего не обходится.
- Вежливость: ограниченная конкурентность (`PARSER_CONCURRENCY=3`), пауза между
  запросами (`PARSER_REQUEST_DELAY`), таймауты, ограниченные повторы с exponential backoff,
  понятный `User-Agent`.
- Данные сайта носят информационный характер (сайт явно указывает, что это не оферта) —
  это отражено в ответах сервиса ссылкой на лот как первоисточник.

## 7. Проверка на реальных данных

Песочница, в которой писался код, не имела сетевого доступа к `dogma.ru`, поэтому структура
API установлена по запросам браузера, а фикстуры (`tests/fixtures`) составлены по реальным
ответам. Реальный сбор выполнен 24.11.2026 в Docker на машине автора:

- первый полный сбор: 7 городов, **14 870–14 882 квартиры** (два запуска с интервалом ~3 ч),
  ~160 HTTP-запросов, ~85 с; число лотов по каждому городу совпало с `count` из API;
- нормализацию прошли все лоты (`invalid = 0`);
- повторный сбор сразу после первого получил от `service.dogma.ru` **HTTP 429** — у
  источника есть ограничение частоты. Заголовок `Retry-After` не приходит, поэтому парсер
  применяет собственные паузы и снижает темп (см. ADR-009).
